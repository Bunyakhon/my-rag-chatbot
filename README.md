# ระบบที่ปรึกษาภาษีเงินได้บุคคลธรรมดา (RAG Assistant)

แอปพลิเคชันถาม-ตอบภาษาไทยสำหรับ **ภาษีเงินได้บุคคลธรรมดา** โดยใช้แนวคิด Retrieval-Augmented Generation (RAG) ระบบจะค้นหาข้อความที่เกี่ยวข้องจากคลังเอกสารภายในก่อน แล้วจึงส่งข้อความที่ค้นพบไปให้โมเดลภาษาใช้ประกอบการตอบคำถาม

โปรเจกต์นี้เหมาะสำหรับการเรียนรู้และสาธิตการสร้างระบบถาม-ตอบจากเอกสารเฉพาะด้าน ไม่ควรใช้คำตอบแทนคำแนะนำจากกรมสรรพากร ผู้เชี่ยวชาญด้านภาษี หรือนักบัญชี โดยเฉพาะกรณีที่เกี่ยวข้องกับกฎหมายหรือกำหนดเวลาซึ่งอาจเปลี่ยนแปลงได้

## ความสามารถหลัก

- สนทนาภาษาไทยผ่านหน้าเว็บ Streamlit
- ค้นหาความรู้จากไฟล์ `.txt` ในโฟลเดอร์ `data/`
- รองรับเนื้อหาเกี่ยวกับเงินได้พึงประเมิน ประเภทเงินได้ ค่าใช้จ่าย ค่าลดหย่อน อัตราภาษี การคำนวณ ภาษีหัก ณ ที่จ่าย การยื่นแบบ และภาษีเงินได้ครึ่งปี
- แสดงชื่อเอกสารอ้างอิงที่ถูกนำมาใช้ตอบคำถาม
- มีคำถามตัวอย่างที่กดเพื่อทดสอบได้ทันที ทั้งคำถามที่อยู่ใน Domain และคำถามนอกขอบเขต
- ล้างประวัติการสนทนาได้จาก Sidebar

## Domain คืออะไร

ในโปรเจกต์นี้ **Domain** หมายถึงขอบเขตความรู้เฉพาะเรื่องที่ระบบได้รับอนุญาตให้ตอบ ไม่ได้หมายถึงความรู้ทั้งหมดของโมเดลภาษา

### Domain ของระบบ

Domain หลักคือ **ภาษีเงินได้บุคคลธรรมดาของประเทศไทย** โดยเอกสารปัจจุบันครอบคลุมหัวข้อเหล่านี้:

1. ความรู้พื้นฐานและผู้มีหน้าที่เสียภาษี
2. เงินได้พึงประเมิน
3. ประเภทเงินได้ตามมาตรา 40
4. การหักค่าใช้จ่าย
5. ค่าลดหย่อนภาษี
6. อัตราภาษีเงินได้บุคคลธรรมดา
7. ขั้นตอนการคำนวณภาษี
8. ภาษีหัก ณ ที่จ่าย
9. การยื่นแบบภาษี เช่น ภ.ง.ด.90, ภ.ง.ด.91 และ ภ.ง.ด.94
10. ภาษีเงินได้ครึ่งปี
11. ตัวอย่างการคำนวณภาษี
12. คำถามที่พบบ่อย

### สิ่งที่อยู่นอก Domain

ระบบไม่ได้ถูกออกแบบมาให้ตอบเรื่องภาษีทุกประเภทหรือคำแนะนำเฉพาะบุคคล เช่น ภาษีนิติบุคคล ภาษีมรดก ภาษีธุรกิจเฉพาะ การวางแผนภาษีที่ต้องวิเคราะห์เอกสารจริง หรือกฎหมายที่ไม่มีอยู่ในคลังเอกสาร เมื่อค้นหาแล้วไม่พบบริบทที่เกี่ยวข้อง ระบบควรตอบว่า:

> ไม่พบข้อมูลในเอกสารความรู้ที่ระบบมี

การกำหนด Domain แบบนี้ช่วยลดการตอบแบบคาดเดา (hallucination) และทำให้ผู้ใช้ทราบว่าคำตอบอ้างอิงจากข้อมูลชุดใด

## แหล่งที่มาของเอกสาร

เอกสารความรู้ทั้งหมดอยู่ในโฟลเดอร์ [`data/`](data/) และเป็นไฟล์ข้อความ UTF-8 จำนวน 12 ไฟล์ ตั้งชื่อเรียงลำดับตั้งแต่ `01_...txt` ถึง `12_...txt` โดยเนื้อหาเป็นคลังความรู้ที่เตรียมไว้สำหรับระบบนี้ ครอบคลุมหลักการและตัวอย่างเกี่ยวกับภาษีเงินได้บุคคลธรรมดา

ก่อนนำไปใช้งานจริง ควรตรวจสอบและบันทึกข้อมูลต่อไปนี้ให้ชัดเจน:

- หน่วยงานหรือเว็บไซต์ต้นทางของแต่ละข้อความ
- วันที่เผยแพร่หรือวันที่ปรับปรุงล่าสุด
- ปีภาษีและช่วงเวลาที่กฎหมายมีผล
- ผู้รับผิดชอบการตรวจทานเนื้อหา

README นี้จึงไม่ควรตีความว่าเอกสารใน `data/` เป็นประกาศหรือคำวินิจฉัยทางกฎหมายโดยอัตโนมัติ ผู้ดูแลระบบควรเทียบกับเว็บไซต์กรมสรรพากรหรือแหล่งราชการล่าสุดก่อนเผยแพร่ให้ผู้ใช้งานทั่วไป

## โครงสร้างโปรเจกต์

```text
.
├── app.py                 # แอป Streamlit และกระบวนการ RAG ที่ใช้งานอยู่
├── rag_engine.py          # โมดูล RAG/การเชื่อมต่อ API อีกชุดสำหรับต่อยอดหรือทดลอง
├── requirements.txt       # รายการ dependency หลัก
├── test_questions.csv     # ชุดคำถามสำหรับทดสอบระบบ
├── data/                  # เอกสารความรู้ภาษีในรูปแบบ .txt
└── README.md
```

## การทำงานของระบบ RAG

เมื่อผู้ใช้ส่งคำถาม ระบบทำงานตามลำดับดังนี้:

1. อ่านไฟล์ `.txt` ทั้งหมดจาก `data/` และทำความสะอาดช่องว่าง/รูปแบบข้อความ
2. แบ่งเอกสารเป็นส่วนย่อย (chunk) ขนาดประมาณ 1,000 ตัวอักษร โดยมีข้อความซ้อนทับกัน 150 ตัวอักษร เพื่อไม่ให้สาระบริเวณรอยต่อหายไป
3. สร้างเวกเตอร์ตัวแทนความหมายด้วย `paraphrase-multilingual-MiniLM-L12-v2` ซึ่งรองรับภาษาไทย
4. เก็บเวกเตอร์ในดัชนี FAISS แบบ `IndexFlatL2`
5. แปลงคำถามเป็นเวกเตอร์และค้นหา chunk ที่ใกล้เคียงที่สุด 3 รายการ โดยใช้ระยะห่างไม่เกิน 25
6. รวม chunk ที่ค้นพบเป็น `Context` แล้วส่งไปยังโมเดล `google/gemini-2.5-flash` ผ่าน OpenRouter
7. กำหนด Prompt ให้โมเดลใช้เฉพาะ Context, ไม่คาดเดา และแสดงคำตอบเป็นภาษาไทย
8. แสดงคำตอบพร้อมชื่อไฟล์เอกสารอ้างอิงในหน้าเว็บ

หากไม่พบ chunk ที่ผ่านเกณฑ์ ระบบจะไม่เรียกโมเดลภาษา แต่ตอบข้อความแจ้งว่าไม่มีข้อมูลในเอกสารแทน วิธีนี้ช่วยลดค่าใช้จ่ายและลดโอกาสที่โมเดลจะตอบจากความรู้ภายนอก

## การติดตั้ง

ต้องใช้ Python 3.10 ขึ้นไป และควรสร้าง virtual environment ก่อนติดตั้งแพ็กเกจ:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

ปัจจุบัน `app.py` import แพ็กเกจบางรายการที่ยังไม่ได้ระบุใน `requirements.txt` ให้ติดตั้งเพิ่มหากระบบแจ้ง `ModuleNotFoundError`:

```bash
python -m pip install faiss-cpu pandas pythainlp
```

บน Windows ให้เปิดใช้งาน environment ด้วยคำสั่งนี้แทน:

```powershell
.venv\Scripts\Activate.ps1
```

## การตั้งค่า OpenRouter API Key

แอปต้องใช้ OpenRouter API Key เพื่อเรียกโมเดลภาษา สามารถตั้งค่าได้ 2 วิธี

### วิธีที่ 1: กรอกผ่าน Sidebar

รันแอปก่อน แล้วกรอก key ในช่อง `กรุณากรอก OpenRouter API Key` ทางด้านซ้ายของหน้าเว็บ วิธีนี้เหมาะสำหรับการทดลองเฉพาะเครื่อง และ key จะไม่ถูกบันทึกลงไฟล์โปรเจกต์

### วิธีที่ 2: ใช้ Streamlit Secrets

สร้างไฟล์ `.streamlit/secrets.toml` ในเครื่อง แล้วเพิ่ม:

```toml
OPENROUTER_API_KEY = "ใส่คีย์ของคุณที่นี่"
```

อย่า commit ไฟล์นี้หรือเผยแพร่ API Key ใน GitHub ควรเพิ่ม `.streamlit/secrets.toml` ใน `.gitignore` หากยังไม่มีรายการนี้

## การรันแอป

จากโฟลเดอร์รากของโปรเจกต์ ให้รัน:

```bash
streamlit run app.py
```

จากนั้นเปิด URL ที่ Streamlit แสดงใน Terminal โดยทั่วไปคือ `http://localhost:8501`

เมื่อเปิดหน้าเว็บแล้ว:

1. ตรวจสอบว่า Sidebar แสดงสถานะ OpenRouter เป็น `Connected`
2. รอให้ระบบโหลด embedding model และสร้างดัชนีเอกสารในครั้งแรก
3. พิมพ์คำถามลงในช่องแชต หรือกดคำถามตัวอย่าง
4. ตรวจสอบคำตอบและชื่อไฟล์อ้างอิงท้ายคำตอบ
5. กด `ล้างประวัติการสนทนา` หากต้องการเริ่มบทสนทนาใหม่

การโหลดโมเดล embedding ครั้งแรกอาจใช้เวลานานและต้องเชื่อมต่ออินเทอร์เน็ต หลังจากนั้น Streamlit จะ cache resource ไว้ระหว่างการทำงานของแอป

## ตัวอย่าง Prompt สำหรับสั่ง AI

คำถามควรระบุบริบทและสิ่งที่ต้องการให้ตอบให้ชัดเจน ตัวอย่างต่อไปนี้ใช้ทดสอบกับระบบได้ทันที

### คำถามพื้นฐาน

```text
เงินได้พึงประเมินคืออะไร อธิบายให้คนที่ไม่เคยยื่นภาษีเข้าใจง่าย และบอกเอกสารอ้างอิงด้วย
```

```text
ค่าลดหย่อนส่วนตัวมีจำนวนเท่าใด และนำไปใช้ในขั้นตอนไหนของการคำนวณภาษี
```

### คำถามที่ต้องการขั้นตอน

```text
ช่วยอธิบายขั้นตอนการคำนวณภาษีเงินได้บุคคลธรรมดาตั้งแต่เงินได้พึงประเมินจนถึงภาษีสุทธิ โดยใช้เฉพาะข้อมูลในเอกสาร
```

```text
ถ้ามีรายได้หลายประเภท ควรพิจารณาการหักค่าใช้จ่ายอย่างไร กรุณาสรุปเป็นข้อ ๆ และระบุแหล่งอ้างอิง
```

### คำถามเชิงเปรียบเทียบ

```text
ภ.ง.ด.90 กับ ภ.ง.ด.91 แตกต่างกันอย่างไร อธิบายเฉพาะตามข้อมูลในคลังเอกสาร
```

### คำถามที่อยู่นอก Domain

```text
ภาษีมรดกมีวิธีคำนวณอย่างไร
```

คำถามนี้ใช้ตรวจสอบพฤติกรรมเมื่อไม่มีข้อมูลที่เกี่ยวข้องในคลัง ระบบควรแจ้งว่าไม่พบข้อมูล แทนการแต่งคำตอบจากความรู้ทั่วไปของโมเดล

### Prompt สำหรับทดสอบการไม่ตอบเกินเอกสาร

```text
ฉันมีรายได้จากต่างประเทศในปี 2026 ต้องเสียภาษีหรือไม่ และมีกฎหมายใหม่อะไรบ้าง กรุณาตอบโดยใช้เฉพาะเอกสารที่ระบบให้มา หากไม่มีข้อมูลให้แจ้งว่าไม่พบข้อมูล
```

คำถามลักษณะนี้ช่วยตรวจว่าโมเดลไม่เติมข้อมูลเรื่องปีภาษีหรือกฎหมายล่าสุดเองเมื่อไม่มีข้อความรองรับ

## แนวทางเพิ่มหรือแก้ไขเอกสาร

1. เพิ่มไฟล์ข้อความ UTF-8 ใหม่ไว้ใน `data/`
2. ตั้งชื่อไฟล์ให้สื่อความหมายและไม่ซ้ำกับไฟล์เดิม
3. แบ่งหัวข้อและเขียนประโยคให้ชัดเจน เพื่อให้ค้นหาได้ตรงคำถาม
4. ระบุปีภาษี วันที่มีผล และแหล่งที่มาไว้ในเอกสาร
5. ทดสอบทั้งคำถามที่ควรตอบได้และคำถามนอก Domain
6. รีสตาร์ต Streamlit เพื่อให้ระบบอ่านเอกสารและสร้างดัชนีใหม่

## ข้อจำกัดและข้อควรระวัง

- คำตอบขึ้นอยู่กับความครบถ้วนและความถูกต้องของไฟล์ใน `data/`
- ระบบค้นหาจากความใกล้เคียงของข้อความ ไม่ได้ตรวจสอบความถูกต้องของกฎหมายโดยอัตโนมัติ
- เกณฑ์ปีภาษีและกำหนดเวลายื่นแบบอาจเปลี่ยนแปลง ต้องตรวจสอบกับกรมสรรพากรเสมอ
- การเรียก OpenRouter อาจมีค่าใช้จ่าย โควตา หรือข้อจำกัดตามบัญชีผู้ใช้
- ไม่ควรใส่ข้อมูลส่วนบุคคลหรือข้อมูลภาษีที่เป็นความลับลงในระบบโดยไม่ประเมินความเสี่ยงก่อน
- ผลลัพธ์จาก AI เป็นข้อมูลประกอบการศึกษา ไม่ใช่คำแนะนำทางกฎหมายหรือการรับรองการยื่นภาษี

## การทดสอบเบื้องต้น

ใช้คำถามจาก [`test_questions.csv`](test_questions.csv) เพื่อทดสอบความครอบคลุมของคลังเอกสาร โดยควรตรวจอย่างน้อย 3 กลุ่ม:

- คำถามที่มีคำตอบชัดเจนในเอกสาร
- คำถามที่ใช้คำเรียกต่างจากในเอกสาร แต่มีความหมายเดียวกัน
- คำถามนอก Domain ซึ่งควรได้ข้อความปฏิเสธที่กำหนดไว้

หลังแก้ไขเอกสารหรือเปลี่ยน threshold การค้นหา ควรเปรียบเทียบคำตอบก่อนและหลังการเปลี่ยนแปลง รวมถึงตรวจว่าเอกสารอ้างอิงตรงกับคำตอบจริง
